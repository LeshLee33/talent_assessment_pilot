# Talent Assessment Pilot

Демо подхода к AI-оценке кандидатов в кадровый резерв банка (пилот, позиция «Руководитель в направлении Data AI»).

> **Только синтетические данные.** Кандидаты вымышленные, баллы не используются для кадровых решений.
> AI рекомендует — решение принимает человек.

В проекте: конфиги методики, вымышленные кандидаты, детерминированный подсчёт баллов,
веб-интерфейс и REST API на FastAPI. **Нет** LLM, симуляций, генерации тестов, PDF и внешних сервисов.

## Быстрый старт (Linux, чистое окружение)

Нужен Python 3.10 или новее.

```bash
cd talent_assessment_pilot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn web.app:app --host 127.0.0.1 --port 8000
```

- Главная страница: http://127.0.0.1:8000/
- Swagger UI: http://127.0.0.1:8000/docs

Тесты: `pip install -r requirements-dev.txt && python -m pytest -q` (см. раздел «Тесты»).

## Веб-интерфейс

- **Главная** (`/`): целевая должность Head of Data AI, число тестовых кандидатов, список кандидатов
  с ID и кнопкой «Открыть оценку», целевой профиль позиции.
- **Оценка кандидата** (`/candidates/{id}`): 6 компетенций с целевыми уровнями; кнопка «Рассчитать оценку»
  вызывает API и показывает оценку 1–5, цель, разницу, индикатор «текущий уровень / цель», категорию,
  общий результат, сильные стороны, зоны развития, рекомендации и флаги качества данных.
  Нажатие на строку компетенции раскрывает индикаторы и исходные баллы по методам.

## API

| Метод | Маршрут | Описание |
|---|---|---|
| GET | `/` | Главная страница (HTML) |
| GET | `/candidates/{candidate_id}` | Страница оценки (HTML) |
| GET | `/api/candidates` | Список кандидатов и целевая позиция |
| GET | `/api/candidates/{candidate_id}` | Исходные данные кандидата по модели компетенций |
| POST | `/api/candidates/{candidate_id}/evaluate` | Расчёт оценки и отчёт |
| GET | `/api/health` | Проверка загрузки конфигов и данных |

Ошибки возвращаются как `{"detail": {"message": "...", "problems": [...]}}`:
404 — кандидат не найден, 422 — некорректные входные баллы, 500 — ошибка в конфигах или `synthetic/candidates.json`.

`POST .../evaluate` без тела считает по сохранённым баллам. Необязательное тело позволяет
посчитать сценарий «что если» (файл данных не меняется), баллы проверяются теми же правилами:

```bash
curl -X POST http://127.0.0.1:8000/api/candidates/CAND-0002/evaluate \
     -H 'Content-Type: application/json' -d '{"scores": {"TM2": {"sjt": 4}}}'
```

## Консольное демо

```bash
python main.py
```

Программа:
1. читает конфиги из `config/` и кандидатов из `synthetic/candidates.json`;
2. проверяет данные (при ошибке выводит список всех проблем и завершается с кодом 1);
3. считает уровни компетенций и сравнивает их с профилем позиции;
4. печатает таблицу в консоль и сохраняет полный результат в `output/results_head_data_ai.json`.

Параметры (необязательные):

```bash
python main.py --position head_data_ai \
               --candidates synthetic/candidates.json \
               --config-dir config \
               --output output/my_results.json
```

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Что проверяется:

| Группа | Что именно |
|---|---|
| Модель компетенций | 6 компетенций и 21 индикатор с нужными id; у каждого индикатора ≥ 2 методов, из них ≥ 1 поведенческий; цели заданы для всех компетенций |
| Расчёт балла | ручной пересчёт индикатора и компетенции; сквозной расчёт по демо-кандидатам |
| Веса 70/30 | веса в конфиге; расчёт на крайних значениях; смена весов в конфиге меняет результат |
| Пропуски | `null` не превращается в 0 ни в индикаторе, ни в компетенции; пропущенный ключ — ошибка |
| Флаг самооценки | ровно ±1.5 — флаг; ±1.49 — нет флага |
| Категории | границы +0.5 / −0.5 / −1.5, в том числе через полный расчёт с округлением |
| Ошибки данных | битые JSON/YAML, баллы вне шкалы, лишние/пропущенные индикаторы и методы, неверные веса и пороги, чужая позиция; CLI завершает работу с кодом 1 |
| Веб и API (`test_app.py`) | API совпадает с движком; общий результат, сильные стороны, зоны развития, рекомендации; 404/422 на неверный ID и баллы; страницы и Swagger открываются |

## Правила подсчёта

Все числа берутся из `config/scoring_rules.yaml`, в коде их нет.

1. **Индикатор** = 70% × (среднее поведенческих методов: SJT, симуляции) + 30% × опросник.
   - Нет ни одной поведенческой оценки → индикатор не оценивается (флаг «недостаточно данных»).
   - Самооценка отличается от поведенческой оценки на ≥ 1.5 → флаг «завышенная/заниженная самооценка».
2. **Компетенция** = среднее по оценённым индикаторам
   (если оценено меньше 50% индикаторов — «Недостаточно данных»).
3. **Разрыв** = уровень − целевой уровень позиции → категория:

| Разрыв | Категория |
|---|---|
| ≥ +0.5 | Сильная сторона |
| от −0.5 до +0.5 | Соответствует требованиям |
| от −1.5 до −0.5 | Зона развития |
| ≤ −1.5 | Критичная зона развития |

4. **Общий результат** (допущение прототипа, раздел `overall_result` в `scoring_rules.yaml`):
   доля оценённых компетенций в категориях «Сильная сторона» / «Соответствует требованиям».

| Доля | Итог |
|---|---|
| ≥ 0.8 | Профиль соответствует целевому |
| ≥ 0.5 | Частичное соответствие профилю |
| < 0.5 | Существенные разрывы с профилем |

   Если есть критичная зона развития, итог не выше «Частичное соответствие».
5. **Сильные стороны** — категория «Сильная сторона»; **зоны развития** — «Зона развития» и
   «Критичная зона развития» (по возрастанию разрыва).
6. **Рекомендации** — детерминированные шаблоны (`engine/report.py`): по критичным зонам и зонам
   развития с двумя самыми слабыми индикаторами, по флагам самооценки и нехватки данных,
   по сильным сторонам. LLM не используется.

## Ограничения демо

- Только синтетические данные; результат не подтверждает реальные качества человека и не используется для кадровых решений.
- Целевые уровни позиции предварительные и не согласованы с HR.
- Правило общего результата и тексты рекомендаций — допущения прототипа.
- Баллы по методам заданы вручную в `synthetic/candidates.json`; самих тестов и симуляций в проекте нет.
- Нет авторизации, базы данных и сохранения истории оценок; приложение рассчитано на локальный запуск (`127.0.0.1`).

| CAND-0005 | неполные данные | Профиль соответствует целевому (по 5 из 6) | компетенция с 1 из 3 оценённых индикаторов, пропущенный опросник |
| CAND-0006 | граничный | Частичное соответствие | разрывы ровно +0.5, −0.5, −1.5 и +0.4 — границы категорий |

## Формат данных кандидата

```json
"ST1": {"sjt": 4, "sim1": 5, "questionnaire": 4}
```

Набор методов у каждого индикатора должен совпадать с матрицей в `competency_model.yaml`.
Если данных по методу нет (например, LLM-судья не нашёл цитат), укажите `null`.
